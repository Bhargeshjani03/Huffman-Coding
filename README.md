# Model Compression Using Huffman Coding

A lossless neural network model compression system using a custom implementation of the **Huffman Coding algorithm**. This project compresses the raw parameter bytes of a trained MNIST model, reconstructs the original weights, and verifies that the model's predictions remain unchanged.

## Overview

Machine learning models often contain large sets of numerical parameters (weights and biases). Storing and deploying these models can be challenging, particularly in resource-constrained environments such as mobile and edge devices.

This project explores **Huffman Coding**, a lossless data compression algorithm, as a method for reducing the storage size of trained neural network models.

A neural network trained on the MNIST handwritten digit dataset is used as the experimental model. Its parameter data is extracted, compressed using a custom Huffman encoder, and stored in a custom binary container format called **HUFC**.

The compressed data is then decoded to reconstruct the original model parameters. Multiple validation checks ensure that the decompressed model is identical to the original model.

## Problem Statement

Develop a lossless compression system for trained machine learning model weights using the Huffman Coding algorithm, implemented from scratch.

The system should:

1. Extract parameter data from a trained neural network.
2. Calculate the frequency of individual symbols in the extracted byte stream.
3. Construct a Huffman tree based on symbol frequencies.
4. Generate variable-length binary codes.
5. Encode the original parameter data.
6. Store the compressed data and required metadata in a custom file format.
7. Decode the compressed file and reconstruct the original parameter data.
8. Verify that the reconstructed model produces identical predictions.

## Objectives

- Implement Huffman Coding without relying on an external compression library.
- Apply the algorithm to actual neural network parameters.
- Design a custom binary container format for storing compressed model data.
- Achieve lossless compression and exact reconstruction.
- Measure compression ratio, storage savings, encoding time, and decoding time.
- Verify that compression does not affect model weights or prediction accuracy.
- Provide a web-based dashboard to visualize compression results and Huffman analysis.

## How It Works

The compression pipeline consists of the following stages:

### 1. Model Training

A Multi-Layer Perceptron (MLP) is trained on the MNIST handwritten digit dataset.

**Model architecture:**

```text
Input Layer:       784 neurons
Hidden Layer 1:    128 neurons
Hidden Layer 2:     64 neurons
Output Layer:       10 neurons
```

The model contains 109,386 parameters.

### 2. Tensor Payload Extraction

The trained model's parameters are extracted and serialized into a raw byte stream.

- Model weights and biases are extracted.
- Tensor metadata is preserved separately.
- Parameter values are converted into their raw byte representation.
- A manifest records the information required to reconstruct the tensors.

The original parameter bytes are preserved without quantization or rounding.

### 3. Frequency Analysis

The frequency of every distinct byte value (0–255) is calculated using a frequency counter.

More frequent symbols are assigned shorter Huffman codes, while less frequent symbols receive longer codes.

### 4. Huffman Tree Construction

A Huffman tree is constructed using a custom implementation of a min-heap and binary tree nodes.

The algorithm repeatedly:

1. Selects the two nodes with the lowest frequencies.
2. Combines them into a new internal node.
3. Inserts the new node back into the priority queue.
4. Repeats until a single root node remains.

### 5. Codebook Generation

Binary codes are generated by traversing the Huffman tree:

- Left edge represents `0`.
- Right edge represents `1`.

Each byte symbol receives a variable-length binary code.

### 6. Encoding

The original byte stream is encoded using the generated Huffman codebook.

The encoded bits are packed into bytes and stored in the compressed container.

### 7. HUFC Container Creation

The compressed data is stored in a custom binary file with the `.huf` extension.

The container includes:

- Magic identifier
- Format version
- Metadata length
- Original payload size
- Encoded payload size
- Valid encoded bit count
- Huffman codebook
- Tensor reconstruction manifest
- SHA-256 checksum
- Encoded binary payload

### 8. Decoding and Reconstruction

The decoder reads the HUFC container, reconstructs the Huffman codebook, and decodes the compressed bitstream.

The original raw parameter bytes are recovered and converted back into their respective tensors.

### 9. Verification

The reconstructed model is compared with the original model using:

- Byte-level equality
- Tensor weight equality
- Prediction equality
- Accuracy comparison

Successful verification confirms that the compression process is lossless.

## Experimental Results

The system was evaluated using a trained MNIST neural network.

### Model Information

| Metric | Value |
|---|---:|
| Dataset | MNIST |
| Model | Multi-Layer Perceptron |
| Total Parameters | 109,386 |
| Number of Tensors | 6 |
| Original Accuracy | 97.29% |
| Raw Parameter Size | 437,544 bytes |

### Compression Results

| Metric | Value |
|---|---:|
| Original Payload | 437,544 bytes |
| Compressed Container | 415,309 bytes |
| Compression Ratio | 1.0535× |
| Space Saved | 5.08% |
| Encoding Time | ~0.178 seconds |
| Decoding Time | ~0.295 seconds |

*Values are from the recorded experimental run and may vary slightly across executions and hardware.*

### Lossless Verification

| Verification | Result |
|---|---|
| Original and reconstructed bytes | Identical |
| Original and reconstructed weights | Identical |
| Original and reconstructed predictions | Identical |
| Accuracy before compression | 97.29% |
| Accuracy after decompression | 97.29% |
| SHA-256 checksum validation | Supported by container format |

The results demonstrate that the implemented compression pipeline preserves the original model parameters and predictions.

**Observation:** The compression improvement is modest. Huffman Coding is most effective when symbol frequencies are sufficiently non-uniform. Raw floating-point parameter bytes may have a relatively distributed frequency pattern, and container metadata introduces additional overhead.

## Limitations

- Huffman Coding operates on individual bytes rather than understanding numerical relationships between model weights.
- Floating-point parameter bytes may not have highly skewed frequency distributions.
- Container metadata and codebook storage introduce additional overhead.
- Compression effectiveness depends on the distribution of symbols in the original payload.
- The current experiment focuses on a single MNIST MLP architecture.
- Compression and decompression performance may vary with model size and hardware.
